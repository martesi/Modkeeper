# 1.8 Frontend Redesign Audit & Gap Analysis

This audit reviews the current frontend structure of Modkeeper against the **Fidelity Modern** Product Requirements Document (PRD). It identifies gaps in visual styling, layout, component reusability, state management, and outlines the migration path.

---

## 1. Feasibility of Current Tech Stack

The current tech stack is highly suitable for implementing the redesigned layout and styling with minimal disruption:
- **Styling (Tailwind CSS v4):** Excellent support for modern features, fluid gradients, and theme-variable mapping.
- **State Management (Jotai):** Perfect for the lightweight, interactive profile and selection state transitions.
- **Routing (@tanstack/react-router):** Clean file-based layout structure already set up. We will simplify/remove routes that are no longer needed (e.g., detail subroutes).
- **Component System (Radix UI / custom shadcn/ui):** All existing interactive elements (Dialog, Switch, Checkbox, Select, Tooltip) use standard accessible primitives, which can be custom-styled to match the redesigned geometries.

---

## 2. Design System Migration (Fidelity Modern)

### Current Styles (`src/assets/style.css`)
- **Accent Color:** Currently `--primary` is set to dark grey/black.
  - **Required Action:** Replace with Primary Pink (`#e91e63`) or its OKLCH equivalent (`oklch(0.586 0.224 8.7)`).
- **Backdrop Blur & Depth:** Currently does not define standard glassmorphic/vibrancy tokens.
  - **Required Action:** Define glass classes in `@layer utilities`:
    - `.glass-standard`: `backdrop-filter: blur(24px) saturate(140%)` with a border tint of `white/10`.
    - `.glass-strong`: `backdrop-filter: blur(40px) saturate(160%)` with a border tint of `white/15` (for dialog bodies).
- **Geometry (Roundedness):** Currently using standard `--radius: 0.625rem`.
  - **Required Action:** Define standard Level 3 geometry:
    - Standard controls/buttons: `rounded-2xl` (`1rem` / `16px`).
    - Dialogs, popups, and card boundaries: `rounded-3xl` (`2rem` / `32px`).
- **Typography:** Enforce `system-ui, sans-serif` as the font family stack for native multilinguistic support.

## 3. Screen-by-Screen Gap Analysis

### Screen 1: Library - Empty State (Activate Library)
- **Current State:** Renders a basic, plain text container stating "No library loaded. Open or create a library from the sidebar."
- **PRD Specification:** A high-fidelity 16:9 central card with a dashed border, cloud upload icon, and a "MANAGE LIBRARIES" button. Hovering transitions the card scale and highlights borders. Clicks open the Manage Library dialog.
- **Layout Gap:** Navigation is currently a top-left/header-nested navigation list (`AppNavigation`). The PRD requires a **bottom-center floating navigation dock** displaying "Home" and "Settings" tabs.
- **Work Items:**
  1. Relocate `<AppNavigation />` into a floating dock component positioned bottom-center on the root layout.
  2. Implement a reusable empty-state card component that handles scaling transitions and pointer changes.
  3. Bind card clicks to trigger the new "Manage Library" dialog.

### Screen 2: Library - Empty State (No Mods / Drop Zone)
- **Current State:** Shows a text block: "No mods installed. Add mods to get started."
- **PRD Specification:** Identical card component to Screen 1. Acts as a drag-and-drop listener for `.zip` archive installation. Clicking it prompts a file picker filtered exclusively by `.zip`.
- **Work Items:**
  1. Reuse the central empty-state card component in Screen 1.
  2. Add active drag-enter/leave listeners to the window/card context that hook up to the Tauri background installation service.
  3. Filter the dialog file selection dialog to only accept `.zip` files, updating the bottom-right badge.

### Screen 3: Library - Title Only View (Grid List)
- **Current State:** Grid list of `ModCard` elements displaying versions, dependency warnings, author names, deletion shortcuts, and open-in-explorer controls.
- **PRD Specification:** A clean grid layout with a top toolbar card and card components stripped of versioning, documentation, or dependency resolution states.
- **Work Items:**
  1. **Toolbar Card:** Create a top panel offering a Select All checkbox, Sort-by-Name selection, Category Filter selector, bulk "ACTIONS [X]" button, and a search input.
  2. **Mod Card:**
     - Remove `react-markdown` overview renderers, SemVer checks, and dependency warnings since custom manifests are removed.
     - Add select checkboxes to the left.
     - Add styled gradient category icon containers in the center-left.
     - Add active status toggles to the right.
  3. **Bulk Actions:** Bind selected mod arrays to the ACTIONS dropdown trigger, enabling bulk enable, disable, delete, and group configurations.

### Screen 4: Dialog - Configure Tool
- **Current State:** **Non-existent.** No executable utility registry or configuration dialog is present.
- **PRD Specification:** Fixed-width modal overlay with blur depth to configure launching executables.
- **Work Items:**
  1. Build a new tool configuration dialog with three input sections: Identity (Name, Icon image selector with browse button), Executable path (with browse button), and Monospace CLI launch arguments.
  2. Bind buttons to Tauri backend tool commands (e.g., `save_tool`, `delete_tool`).

### Screen 5: Dialog - Manage Library
- **Current State:** Spanned across a sidebar dropdown (`InstanceSwitcher`) and individual popups (`RenameLibraryDialog`, `CloseLibraryDialog`, `RemoveLibraryDialog`).
- **PRD Specification:** A single, consolidated dashboard modal overlay for profile/library settings.
- **Work Items:**
  1. **Tabs Navigation:** Renders horizontally at the top, allowing the user to select libraries. Active profile has a pink background. Dashed `+` tab opens folder selection.
  2. **Identity Section:** Displays editable name string with a Save shortcut.
  3. **Paths Card:** Displays game path, copy to clipboard trigger, and open folder shortcut.
  4. **Tools List:** Shows registered executables, providing a play icon button (Launch) and settings gear button (Configure Tool).
  5. **Footer Actions:** Rebuild Cache, Delete Library (triggers a warning checklist dialog to optionally wipe directories), and Activate (switches/disables when active).

### Screen 6: Settings View
- **Current State:** Renders inside vertical tabs ("General", "Developer") in the center of the window.
- **PRD Specification:** Single column row component stack, category icons, labels, descriptions on the left, theme/accent swatches and dropdown controls on the right.
- **Work Items:**
  1. Deprecate Tab-based divisions.
  2. Implement settings rows inside a single list container.
  3. Hook up theme toggles and accent swatches to apply CSS variables to the document element.

---

## 4. Unused Features to Deprecate/Remove
- **Mod Details View (`src/routes/library.$id.lazy.tsx`):** Since individual mod manifests are removed, this detailed sub-route is no longer planned. Clicking on a mod card does not navigate to a detail page. This route can be safely deleted.
- **Dependency Utilities (`src/utils/dependency-check.ts`):** Drop SemVer and dependency checks.
- **Individual Dialogs (`src/modules/mod-list/*-dialog.tsx`):** Remove close, rename, and delete dialog modules, consolidating them into the unified **Manage Library** dashboard.
