## Mixed Paradigm Violations

### 1. `core/mod_fs.rs`
- **Current:** Uses `ModFS` struct as a container for data AND logic (e.g., `resolve_id`, `infer_mod_type`).
- **Refactor:** Move logic to pure functions that take data structures as input. `ModFS` should be a plain DTO.

### 2. `utils/*.rs`
- **Current:** Files like `file.rs`, `toml.rs`, `process.rs` use the "Struct with Static Methods" pattern (e.g., `FileUtils::copy_recursive`).
- **Refactor:** Remove the empty structs and expose top-level functions.

## OOP Justification

The following files legitimately require OOP because they manage mutable state that must be encapsulated or have long-lived identities:

- `core/library.rs`: Encapsulates the state of a mod library, including its dirty flag, cache, and paths.
- `core/registry.rs`: The central hub for application state, requiring thread-safe mutable access via `Mutex`.
- `config/global.rs`: Manages the global configuration file and its in-memory representation.
